# Chargen slice 6: chargen-dnd — the D&D 5.5e Champion Fighter, 1 to 3

## Problem

Every character the app can build is Pathfinder 2e. The vision's third
pillar — a system-agnostic core, kept honest by building multiple systems
early — is so far a claim backed by one system. The survey ahead of this
slice found the honest state: the engine, wire types, sheet contract, and
decision log carry no game vocabulary — but the server, the WASM bundle,
the checks, the rules-data file set, and the roster all hold exactly one
engine, chosen at compile time, and neither a campaign directory nor a
character file names its game.

This slice adds the **D&D 5.5e Fighter** (SRD 5.2.1 content only),
created at level 1 and leveled to 3 through the existing creation wizard
and level-up machinery, so the Champion subclass at level 3 is a real
choice slot. It is the cross-system stress test the roadmap planned: binary
proficiency against ranks, background-coupled ability scores against
boosts, subclass at 3 against 1, weight against Bulk. The boundary is
expected to bend; the deliverable includes an honest account of where.
Rolled ability scores — the app's first dice — were split out on
2026-09-06 into the follow-up slice `dnd-dice` so this slice makes one
claim: the boundary holds.

## Requirements

1. **A second system exists end to end, chosen per campaign** (decided
   2026-09-06). A campaign directory plays one game: Pathfinder 2e or
   D&D 5.5e. An empty campaign asks once, in the app, which game it
   plays; the answer is written into the campaign atomically and
   create-exclusively (a racing second answer is rejected, never
   overwrites). The declaration can be changed in the app only while
   the campaign holds no characters — a `trash/` holding characters
   counts as holding characters — and is fixed once one exists. A
   campaign that already holds characters but no declaration reads as
   PF2e on every load and is never asked; the app never writes a
   declaration into it. A corrupt or unrecognized declaration
   quarantines the campaign as a whole with the reason; a directory
   with no declaration whose characters name 5.5e is reported as a
   missing declaration, not inferred PF2e. Every pre-slice data
   directory keeps working untouched. A 5.5e campaign's characters run
   through the same guided creation dialog (checklist, live validation,
   per-confirm durable saves, non-linear navigation, resume after tab
   close or server kill) and the same level-up dialog as PF2e
   characters. No second wizard, no second level-up flow: the dialog
   machinery is reused unchanged, as the one-dialog-machine decision
   requires. The roster shows which game the campaign plays;
   per-character system choice and mixed-system campaigns are out of
   scope.
2. **5.5e level-1 creation follows the published 5.5e sequence**: class
   (Fighter), origin (background, then species), ability scores, class
   choices (skills, Fighting Style, weapon masteries), starting
   equipment (one of the class's equipment packages or its gold
   alternative), details. A background's ability-score increases are
   a **choice slot** at the origin step — the player distributes the
   published increase pattern among the background's three abilities —
   and it also grants its origin feat, skill and tool proficiencies;
   a species' internal choices (the Human's extra skill and second
   origin feat) are slots too. Fixed level-1 features (Second Wind,
   Weapon Mastery) land as derived sheet content, never as picks.
3. **Ability scores are generated by Standard Array or Point Buy**,
   chosen at the ability-score step: assign the published fixed set, or
   spend the published budget under the published cost table with a live
   meter and an overspend that is illegal on the checklist with the rule
   named. The background's distributed increases apply on top through
   derivation; a later score change that invalidates the distribution
   lands on the checklist, never clamps silently. The published cap is
   enforced by the validator but is unreachable by hand this slice
   (array or buy plus increases cannot exceed it); rolling in
   `dnd-dice` exercises it. The step's method choice must leave room
   for rolling as a third option without redesign.
4. **Level-up to 3 works for the 5.5e Fighter** through the existing
   pending-level machinery: level 2 grants fixed features (Action Surge,
   Tactical Mind); level 3 opens the **Fighter Subclass** slot — the
   Champion is the one shipped option, and it is a real slot with a real
   catalog, not a hard-coded feature — plus the Champion's level-3
   features. Hit points at each level use the published fixed value.
   The gains panel, finalize deltas, abandon, crash-resume, and
   clone-mid-level all work exactly as they do for PF2e, because they
   are the same code.
5. **The 5.5e sheet is right**: hit points, Armor Class from the worn
   armor's formula (unarmored when nothing is worn), saving throws with
   proficiency, skill bonuses with binary proficiency, attack and
   damage for the carried weapons with mastery properties named (an
   empty attacks section when nothing is carried, never an error),
   speed, initiative, passive Perception, carried weight against
   carrying capacity, coin, features with rules text. The Magic
   Initiate origin feat (granted by two of the SRD's four backgrounds)
   renders with its rules text and a visible "spell choices not yet
   supported" note, so the gap is legible rather than a sheet that
   looks complete. Rendered through the unchanged presentation
   contract — the sheet is a projection with 5.5e's own sections and
   labels, and the UI learns nothing about either system.
6. **The core stays game-free, by tooling.** Engine-core and the wire
   types gain no 5.5e (or PF2e) vocabulary; the new ruleset lives in
   its own crate that never imports the PF2e crate and vice versa; the
   layering, class-isolation, and purity checks extend to cover the
   new crate. Every PF2e golden and fixture stays byte-identical; the
   PF2e ruleset crate changes only where the boundary itself forces a
   change, and the report lists each such change.
7. **Where the boundary bent is a deliverable.** The report carries a
   section listing every place a "one system" assumption was found and
   what replaced it (engine selection, rules-data loading, the roster's
   class list, the version guard, the checks' allowlists, UI copy, the
   campaign and character files), so the vision's boundary claim is
   revised with evidence rather than restated.
8. **Files know their system.** The campaign declaration and every
   character file written from this slice on name the ruleset
   explicitly; a file with no system name reads as PF2e everywhere,
   including the mismatch check, and gains its name on its next wizard
   write. A character file whose system does not match its campaign's,
   or whose system name disagrees with its rules-version pin, is
   quarantined and reported on the roster like a corrupt file, never
   misread through the wrong rules. Rules-version pins, the current
   version, and the older-known set are **per ruleset**; the system
   check runs before the version guard, so a file is never offered a
   version resolution under another system's rules. `verify`, version
   flags, clone, and random mint all work in a 5.5e campaign: mint
   produces a Standard-Array Fighter (array assigned at random) with a
   random legal background, distribution, species, style, masteries,
   and equipment package. Quick build is absent from a 5.5e campaign's
   roster (the SRD publishes no suggested build).
9. **Rules data is SRD 5.2.1 content under CC BY 4.0**, versioned and
   attested like PF2e's: stable IDs, per-record license metadata naming
   the SRD and its attribution text, the required attribution notice
   displayed beside the ORC notice, and every record attested by the
   reference-check pipeline against a published copy of the SRD whose
   provenance (source, hash, page) is recorded. Breadth is a
   representative subset exercising every mechanism, finalized against
   the SRD at implement: three or four of the SRD's nine species
   (the Human among them, for its internal choices), the SRD's four
   backgrounds, its four origin feats, the Fighter with its four
   fighting styles, all weapon masteries with enough weapons to
   exercise every mastery property, the armor list, and the
   starting-equipment packages with the gold alternative. Every subset
   leaves at least one legal option for every legal prior build,
   mint's random path included. Full SRD breadth is growth-track data
   work.
10. **Everything that exists keeps working**: the PF2e creation wizard,
    level-up, quick build, random mint, clone, version flags, and
    `verify` are unchanged for PF2e campaigns.

## User stories & flows

- **The second campaign.** Ben starts the server on a fresh data
  directory; the app asks which game this campaign plays and he picks
  D&D 5.5e. The roster says so. He taps Create, names "Brannock", and
  walks the 5.5e sequence: Fighter; the Soldier background — distributes
  its increases (+2/+1 among its three abilities) and watches them and
  its origin feat land in the sidebar; Human, picking its extra skill
  and second origin feat; Standard Array assigned; two skills; a
  Fighting Style; three weapon masteries; equipment package A.
  Finalizes, and lands on a sheet whose AC, HP, saves, attacks, and
  skills match a hand calculation from the SRD.
- **The buy.** On a second character Ben chooses Point Buy: a meter shows
  the budget draining per the cost table; overspending is illegal on the
  checklist with the rule named; the background increases stack on top
  as distributed and the sidebar shows the result live. He takes the
  gold alternative instead of a package, finalizes, and the sheet shows
  the coin, unarmored AC, an empty attacks section, and six scores and
  modifiers matching the buy plus the increases.
- **The level 3 subclass.** Ben levels Brannock to 2 (gains panel: Action
  Surge, Tactical Mind, HP by the fixed die value) and starts 3: the
  checklist shows one slot, Fighter Subclass, with the Champion as its
  option. He abandons once — the confirm lists the Champion pick — then
  levels again; kill -9 inside the pending level resumes there. He
  finalizes: the deltas list Improved Critical and Remarkable Athlete,
  and at 3 the cap note appears, as it does for PF2e.
- **The crash, again.** kill -9 mid-creation after the ability scores
  were confirmed; restart; resume lands at the exact step, choices intact.
- **Two campaigns, one app.** Ben runs the server on his PF2e directory:
  no game question, Torvald and Sylvenne unchanged, and the roster says
  Pathfinder 2e. He restarts it on the 5.5e directory: Brannock, and the
  roster says D&D 5.5e; open, clone, level, mint, and `verify` all work
  there, and no quick-build control is offered. On a third, fresh
  directory he answers Pathfinder 2e and gets the unchanged PF2e wizard.
- **The wrong drawer.** Ben copies Brannock's file into the PF2e
  campaign's characters directory: the roster reports it quarantined
  with the reason (a 5.5e character in a Pathfinder campaign) and every
  other character loads; nothing rewrites the file.
- **The skeptical inspection.** The campaign directory carries a small
  declaration naming its game; Brannock's file names it too, and its
  decision log reads as the sequence of picks he made, in order, with
  provenance. Tampering with the sheet is caught by `verify`.
- **Nothing else moved.** Torvald's file opens unchanged; a fresh PF2e
  character runs through the unchanged wizard; every PF2e level-up story
  from the previous slice still walks.
- **Unhappy path — jumping ahead.** In the 5.5e wizard Ben goes to
  equipment before choosing a Fighting Style; the step works with what
  is known and the checklist lists the gaps, exactly as the PF2e wizard
  does. He goes back, picks the style, and the sheet's attack lines
  re-derive.

## Risks

- **The boundary bends further than expected.** The survey found the
  single-engine assumption in five places and no system id on files. The
  risk is that generalizing engine selection turns into a framework. The
  architecture dialogue owns the mechanism; this spec's requirement 7
  makes every bend a listed, evidenced change rather than an accretion.
- **The one-dialog-machine claim meets a system it was not shaped by.**
  5.5e's ability-score step is a method choice followed by a
  method-shaped editor (array assignment or budget spend) — richer than
  any PF2e slot view, and it must also leave a door for the rolling
  method. If the slot-view kinds cannot express it without UI branching
  on the system, the report says so and the claim is revised
  deliberately.
- **Licensing.** SRD 5.2.1 content is CC BY 4.0: mechanics and text are
  shippable verbatim with the attribution notice; product-identity
  content is simply absent from the SRD. Re-verified against the actual
  license text before merge; the subset is chosen so nothing outside the
  SRD is needed. **Accepted** residual: the official SRD ships as PDF
  only. The attestation source is bounded now, not searched at
  implement: a timeboxed look for a machine-readable copy with clear
  provenance, otherwise text extracted from the official PDF with its
  hash and page provenance recorded — the report says which.
- **Transcription errors** in a second system's tables (proficiency
  bonus, point-buy costs, mastery properties, carrying capacity).
  Mitigated by attestation plus hand-verified golden builds at 1 and 3.
- **If the slice proves too big at implement**, the designated first cut
  is creation-first: the campaign declaration, the 5.5e ruleset at level
  1 with both score methods, and the boundary report — whose claim is
  then explicitly "holds at level 1"; levels 2 and 3 with the subclass
  slot follow as `dnd-champion`. Recorded, not executed.
- **Accepted:** a campaign's game is fixed once it holds a character —
  there is no changing it after that, and no mixed-system campaign.
  Testing both systems means two data directories, which the existing
  data-dir flag already supports.
- **Accepted:** rolled ability scores and rolled hit points are not
  offered; the `dnd-dice` slice brings rolling as recorded inputs
  (design decided 2026-09-06: the app rolls or the player enters
  physical dice, tagged; every rolled set stays in the log; rerolls
  allowed and visible; reroll policy is table policy for a later epoch).
- **Accepted:** Magic Initiate ships without its spell choices, with the
  gap made visible on the sheet; a 5.5e spellcasting slice owns it.

## Out of scope

- Rolling for ability scores or hit points — `dnd-dice`, the next slice.
- Any 5.5e class beyond the Fighter, any subclass beyond the Champion,
  levels 4+ (the Ability Score Improvement feat at 4 is growth track).
- Spellcasting in 5.5e in any form (Magic Initiate's spell choices are
  not a slot; no Eldritch Knight).
- Multiclassing; feats beyond origin feats; reroll policy; DM-configured
  table rules; DM overrides (edits-and-exceptions); a 5.5e quick build.
- Conversion between systems; per-character system choice; mixed-system
  campaigns; changing a campaign's game once it holds a character;
  multiple campaigns per server process.
- Full SRD breadth (growth track); Starfinder 2e (slice 8).

  gold alternative and hand-verify the coin and the unarmored AC.

  the fixed value, proficiency bonus, the Champion's features on the
  sheet. Walk the abandon and the mid-level crash on Brannock once; they
  behave as the PF2e level-up did.
- Walk "the crash" mid-creation and confirm exact resume.
- Walk "two campaigns, one app": the PF2e directory never asked and
  labeled; the 5.5e directory with open, clone, level, mint, and
  `verify` all working and no quick build; mint one and hand-verify it
  like Brannock; a fresh directory answered Pathfinder 2e gives the
  unchanged wizard. Then walk "the wrong drawer" and confirm the
  quarantine names the reason and the file is untouched.
- Walk "the skeptical inspection": read the campaign declaration and
  Brannock's file — legible? Tamper with the sheet; `verify` catches it.
- Walk "nothing else moved": open Torvald and Sylvenne, create a fresh
  PF2e character, and level a PF2e character to 3 — all unchanged.
- Read the report's "where the boundary bent" section: does each bend
  read as a deliberate generalization you would defend, or as a patch?
- Spot-check three shipped 5.5e records (a species, a background, a
  weapon with a mastery) against the SRD for fidelity and license
  tagging; confirm the CC BY attribution notice is displayed and correct.
- Intent check on the cross-system feel: does creating a 5.5e character
  feel like the same app with different rules, not a second app?
- Intent check on the ability-score step: does the method choice read
  as a place a "Roll" option will slot in later without a redesign?
